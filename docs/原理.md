# 原理

这套东西由三个角色组成，各干一件事。

```
┌─────────────────────┐        ┌──────────────────────┐        ┌──────────────────────┐
│  插件（界面）         │        │  主控端（大脑）        │        │  被控端（手脚）        │
│  Harness 里的一个面板 │◀──────▶│  Node 服务 :7800      │◀──────▶│  同事电脑上的代理      │
│  纯 DOM，零依赖       │  HTTP  │  AI 循环 / 任务调度    │ 长轮询  │  只跑命令，不碰模型    │
└─────────────────────┘        └──────────────────────┘        └──────────────────────┘
                                        │
                                        ▼
                                 DeepSeek API（Key 只在这）
```

---

## 一、为什么 AI 放在主控端

被控端只做三件事：**领任务 → 执行 → 回结果**。

- 不需要在被控端装模型运行时
- 不需要把 API Key 发到别人电脑
- 安装包能压到 33 MB
- 换模型、换提示词只改主控端

---

## 二、插件是怎么工作的

插件是 Harness 的一个**客户端插件**，但刻意做成了"零依赖"形态：

| 事实 | 说明 |
| --- | --- |
| 挂在 `document.body` 上 | 一个 `position:fixed` 的按钮（左下角），**不占用 Harness 的插槽** |
| 不用 React | 面板全部用原生 DOM 构建（`createElement`） |
| `inject: []` | 不声明任何服务依赖，因此不会因为抢跑把别的插件带崩 |
| Node 半边只做一件事 | 启动时探测 `127.0.0.1:7800`，没在跑就拉起主控端（隐藏窗口） |

**历史上踩过的坑**（记录在此，避免重犯）：

- 早期版本注册到 `sidebar.footer.action`，而侧栏折叠时该区域被 `display:none` → 按钮"消失"
- 更严重的一次：插件 `inject: []` 却直接使用 `ctx.slots`，在 UI 依赖未就绪时抛异常，**把 `ui-conversation` 带崩**，连锁导致 12 个界面插件不激活，Harness 启动失败
- 结论：要么把依赖声明写全（像 `dsh-purge` 那样），要么干脆不碰插槽。现在选了后者。

## 三、主控端在做什么

### 1. HTTP 服务（零依赖 `node:http`）

| 接口 | 作用 |
| --- | --- |
| `/` | 网页面板（备用入口） |
| `/join` | 一行命令接入用的引导脚本 |
| `/download/lite.zip` | 下发被控端负载 |
| `/api/agent/*` | 被控端专用（poll / heartbeat / result / event / bundle） |
| `/api/ai/*` | 对话式执行（run / job / stop / plan） |
| `/api/nodes*` | 节点管理（列表、改名、冻结、更新、自毁） |
| `/llm/*` | 模型网关：把请求转发到 DeepSeek，注入真实 Key |

### 2. AI 执行循环

```
用户一句话
   ↓
放进 messages（system 提示规定：单条命令 20 秒内、禁止整盘递归…）
   ↓
调 DeepSeek（function calling，工具是 run_shell）
   ↓ 模型返回 tool_calls
给被控端下发 shell 任务（timeoutMs=120s）
   ↓ 等结果（最多 120 秒）
把输出塞回 messages 作为 tool 消息
   ↓
再问模型 —— 直到它给出文字结论（最多 40 步）
```

关键实现点：

- **每一步都落盘**：`data/ai/<jobId>.json`，重启后能把历史读回来（未完成的标为 `interrupted`）
- **实时输出**：`GET /api/ai/job/:id` 会把正在跑那条命令的日志尾部一起返回，面板才能"边跑边看"
- **停止即杀**：`/stop` 不只是不再派新活，而是找到当前 `taskId` 下发 `cancel` 任务，对端 `taskkill /T /F` 杀整棵进程树（实测 300 秒命令 277 ms 结束）
- **依赖顺序**：`taskId` 必须在"下发后、等待前"写到 step 上，否则停止时找不到目标（这个 bug 修过一次）

### 3. 会话与安全

| 机制 | 位置 |
| --- | --- |
| 控制台口令 | `data/password.txt`（首次启动生成） |
| 登录会话 | `data/sessions.json`，60 天有效，**落盘**，重启服务不掉 |
| 登录限速 | 同 IP 10 分钟错 8 次返回 429 |
| 节点令牌 | 每台一个，服务端只存哈希 |
| 自助登记钥匙 | `data/enroll-key.txt`（打在安装包里） |

## 四、被控端是怎么工作的

### 1. 安装时自动登记

```
读包内 fleet/enroll.json（control 地址 + 登记钥匙）
   ↓
POST /api/agent/enroll  → 服务端发一个专属令牌
   ↓
写回 fleet/fleet.json，注册自启，启动
```

对方**不需要填任何东西**，也不需要 API Key。

### 2. 运行循环

```
心跳（15s）→ 长轮询领任务（wait=25s）→ 执行 → 回传结果
```

- 长轮询：有任务立刻返回，没任务挂起，不占 CPU
- 多任务：默认 2 个并发槽
- 命令超时：默认 180 秒，到点杀进程树
- 输出流式回传（`/api/agent/event`），主控端写进任务日志

### 3. 任务类型

| kind | 作用 |
| --- | --- |
| `shell` | 跑 PowerShell（UTF-8 前导，防中文乱码） |
| `file_get` / `file_put` | 取/传文件 |
| `dir` | 列目录（JSON） |
| `screenshot` | 截屏，PNG base64 写进日志 |
| `cancel` | 杀掉指定任务的进程树（不受并发槽限制） |
| `update_agent` | 拉新代码自我重启 |
| `purge` | 远程自毁 |

### 4. 自启方式

| 模式 | 手段 |
| --- | --- |
| 用户模式（默认推荐） | `HKCU\...\Run\DSHFleet` → `wscript` 隐藏启动 |
| SYSTEM 模式 | 计划任务（开机 + 延迟 30 秒）+ 看门狗（每 5 分钟） |

用户模式**不依赖任务计划程序**，很多公司策略禁用它。

## 五、数据都在哪

```
主控端\
├─ data\
│  ├─ password.txt      控制台口令
│  ├─ enroll-key.txt    登记钥匙
│  ├─ sessions.json     登录会话（60 天）
│  ├─ state.json        节点清单
│  ├─ tasks\            每条任务的 JSON + 输出日志（超过 2000 条自动清）
│  └─ ai\               每次对话的步骤记录
└─ upstream-key.txt     模型 Key（只在主控端）

被控端（对方电脑）
└─ %LOCALAPPDATA%\DSH Fleet\
   ├─ node.exe          自带运行时
   └─ fleet\
      ├─ fleet.json     地址 + 专属令牌
      ├─ agent.log      运行日志
      └─ run-agent.vbs  隐藏启动器
```

## 六、一次完整调用（时序）

```
面板：你说"看看 C 盘哪些目录最占空间"
  → POST /api/ai/run
主控端：建 job，调模型
  → 模型要跑 Get-PSDrive / Get-ChildItem -Depth 2
  → POST /api/ai/job/:id 状态里有 tool 步骤（带 taskId）
被控端：长轮询拿到任务 → 跑 PowerShell → 流式回传输出
主控端：等任务结束 → 把输出塞回模型 → 模型给结论
  → job.steps 里多一条 type=answer
面板：每 800ms 拉一次 job，边跑边显示；你随时点 ■ 停止
```
